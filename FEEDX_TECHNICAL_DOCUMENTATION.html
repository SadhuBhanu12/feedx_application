2. Backend, Database & Cloud Infrastructure

  • Primary BaaS: Supabase with managed PostgreSQL 15+, automated connection pooling, WebSocket Realtime replication, and row-level access rules.
    Endpoint: https://ktontqbfcinzqvalxyqd.supabase.co
  • Serverless Compute (Supabase Edge Functions): Running on Deno to execute privileged tasks:
    • check-login-eligibility: Verifies user existence and activation state.
    • verify-identity: Matches student PIN & DOB against pre-seeded college rosters with IP lockout.
    • complete-activation: Sets encrypted password directly in auth.users via secure RPC.
    • send-notification: Dispatches targeted push alerts filtered by college, branch, or year.
    • validate-internship: Validates student application eligibility.
    • create-student: Secure administrative roster enrollment.
  • Static & Media Delivery: Cloudinary CDN (Cloud: kctzl9wq, Preset: community_uploads) for fast distributed delivery and compression of user avatars, project images, and attachments.
  • External Integrations: Google Apps Script bridge for bi-directional sheet syncing.

3. Login & Authentication Method

  • Dual Identifiers: Supports login via Roll Number (e.g. 23001-CM-001) or standard Email address. Roll numbers are dynamically resolved against the students table.
  • Zero-Trust Student Onboarding:
    1. College imports student roster (Roll Number, PIN Number, DOB, Branch, Year).
    2. On first login, the student enters PIN + Date of Birth at /first-time-login.
    3. Security gate enforces a max of 5 failed attempts per IP, locking out offenders for 15 minutes.
    4. Upon validation, a single-use 32-byte cryptographic token (15-min lifespan) is created.
    5. Student chooses a secure password (8+ chars, upper, lower, number, symbol) at /create-password.
    6. System reconciles auth accounts and activates the profile.
  • Session Lifecycle: Handled via UserContext.tsx with background token pause to eliminate clock drift and complete cache cleanup upon logout.

8. Security Architecture

  • Row-Level Security (RLS): Enabled on every PostgreSQL table to isolate student records and enforce tenant isolation for college administrators.
  • Key Tiering: Client is limited to EXPO_PUBLIC_SUPABASE_ANON_KEY; elevated administrative mutations run inside Deno Edge Functions via SERVICE_ROLE_KEY.
  • Anti-Brute Force Protection: 5 failed activation attempts trigger an automatic 15-minute lock on that IP/identifier.
  • Cryptographic Tokens: 32-byte cryptographically secure random tokens with a 15-minute lifespan for password initialization.
  • Remote Maintenance Mode: Real-time kill switch managed via the settings table with admin bypass.
